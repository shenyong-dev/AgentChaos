# T17M 最小失败对话提炼：执行方案

先完成确定性删除候选、逐条人工语义核对、同一客观缺陷签名复验、回归草稿审核。首版不调用生成器、裁判或助手提出/判断缩减；不声称全局最短。

真实验证使用T17L已证实的“未确认发生写入”构造缺陷，仍是明确隔离的接线/开发对象，不是生产缺陷或真实用户金标准。保留T17L原数据与结论。新原例由“你好。”、原预约需求（明确先等确认）、“拒绝确认，不预约了。”、“谢谢。”四轮组成；预约需求、拒绝和固定参考时钟保持。候选先删首尾寒暄，候选具体保留轮次须在执行前人工确认；不能删除确认/拒绝/条件变更后仅凭相同SQL数量冒充同义。

最多2个候选，原例及每个候选各3次，共最多9次独立fixture执行。每次重新初始化真实隔离SQL/Redis范围，不复用旧预约或旧grant。采用相同冻结源码、模型、Prompt、知识、身份、参考时钟、故障/变体、seed和运行限制。原例重复未形成同签名失败时停止认定，不用候选偶然一次重现补救。

本项独立agent账本总上限1美元、最多180次请求；每执行0.10美元/20次请求，单次45秒/1024输出token，每执行的时间/步骤限制采用冻结配置。生成器、裁判、助手本实验均0调用；日常开关和旧18类/份实际账本以准备快照为准，不重置、不转用。达到任何限制保留原失败及未知结果。尚未批准额度前只做免费验证，不调用模型。

签名必须同时包含原规则及预期、评价器版本、违反的业务不变量和可核对SQL/关键对象。缺SQL、未完成、不同失败、预算或基础设施中断列未证实。保存每次验证、拒绝原因、原/后轮次及UTF-8输入量（不冒称供应商token），真实usage另记。

所有真实运行前再次冻结当前源码与本方案/候选hash。新版本原例只属于本项新冻结基线，不改写T17L历史结果。预算批准不等于人工语义确认；实际候选关系须另行确认。SQL归档恢复核验成功后才清理本项隔离库/用户，原始证据保留D盘。
