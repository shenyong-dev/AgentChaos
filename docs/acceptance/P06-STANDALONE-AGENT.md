# P06 独立进程示例接入

2026-11-17。用户暂时没有其他开发者的候选 Agent，按要求自建[售后工单分流 Agent](../../backend/examples/standalone_support_agent/README.md)。Agent 使用标准库和独立 SQLite 台账，领域逻辑与 HTTP 适配分开。平台沿用现有逻辑，实际完成服务端登记、检查连接、登记版本、填写并审核用例、预检和运行。

| 场景 | 本地真实结果 |
| --- | --- |
| 三轮商品破损 | Agent 从前一轮保留测试订单号，根据描述给出补照片指引。回复字面检查和证据完整性通过。[运行记录](http://127.0.0.1:18066/runs/16b18f75-5488-4842-9d76-0b897aab1f3a) |
| 三轮物流查询，最后一轮模拟丢回执 | Agent 提交事务后省略 HTTP 响应。平台将第三轮标为待查明。手动按原键查到物流回复，页面显示补录回执。原执行保留错误状态，未追加文本判定或重发输入。[运行记录](http://127.0.0.1:18066/runs/9f38412b-cefb-430f-8985-9b3b67738842) |

平台使用独立 MySQL schema、Redis 和 Worker 队列。SQLite 只读核对了 2 个独立会话、2 个准备回执、6 个执行回执及 1 次丢失控制。补录内容和原键哈希吻合。示例无外部模型依赖，记录的模型调用、token、费用均为 0。本轮未部署云端。

审查发现换单时可能沿用旧问题类型，已在运行前修复。浏览器验证后补了 SQLite 显式关连接，最终源码的 4 项离线检查和 Ruff 通过，覆盖换单、重开台账后查证、同键隔离、提前取消和非法限额。保留两条真实运行，未为连接关闭修复重跑。私有取证在 `.local/p06-standalone-agent-20261117`。

本次验证了自建独立进程按 HTTP v1 接入。P06-D 中第三方开发者维护的 Agent 仍待实际候选。
