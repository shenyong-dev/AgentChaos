# T17J 可靠性结果与证据展示验收

入口：测试工作台 → 打开已有运行 → 默认“结果概览”。主开发地址为 `http://127.0.0.1:5173`，以本机实际服务为准。

1. 选择一条执行，不先读JSON，核对五段：测试预期、条件与实际故障、Agent行为、SQL业务事实、保存判定。使用“原始输入与目标”和冻结条件核对原输入、参考时钟、知识修订与故障配置。
2. 对未通过项点击“核对判定”，应进入对应执行、原评价版本和断言；核对预期、实际与原因。点击SQL快照或注入事件，应定位同一执行的原始证据。
3. 分别查看通过、安全降级、业务未通过、等待输入、取消、平台错误、SQL缺失、证据指纹不匹配、配置故障未触发的记录。缺SQL显示未知；等待、取消和平台错误不算Agent业务失败；原规则通过但证据无法核对时摘要不标通过。
4. 在“维度与样本”切换来源/数据分区分组。按“分母与排除项”重算有效规则与任务达成分母；安全降级不混入目标达成。展开维度样本，核对引用规则；未发生确认、参数检查或原键恢复的流程不能显示已覆盖。
5. “查看AI记录”仅进入原辅助评价页，不自动调用。不同来源不合并为成绩；此页没有综合可靠性分，不改变T16无改善与T17B受限辅助结论。
6. 深浅主题、390/320窄屏和键盘可使用执行选择、信息提示与证据按钮。摘要读取失败后旧成功状态应撤下；切换运行/账号后的迟到回复不能恢复旧数据。

已有主库记录不足以覆盖全部状态时，自动化使用明确标记的离线传输控制例；它们不代表真实模型质量。数据库专项在自有隔离库用真实MySQL/Redis与OfflineGateway验证，不创建主库预约或付费实验。最终检查数量与限制见 `docs/evidence/T17J/final-report.json`。
