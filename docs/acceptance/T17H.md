## 日常自己怎么启动

在 `D:\AgentChaos` 的 PowerShell 中：

```powershell
powershell -File scripts/workers.ps1 -Action start
powershell -File scripts/workers.ps1 -Action status
powershell -File scripts/workers.ps1 -Action logs
powershell -File scripts/workers.ps1 -Action stop
```

启动同时管理 Worker 和 Dispatcher。看见容器 running 后，还需打开工程环境重新检测，确认源码/数据库/队列及近期调度扫描匹配；模型调用条件另看预算和开关。启动脚本不会替你开启付费、重置额度或安装环境。

日常启动会面对当前配置的队列；本轮团队验收请优先使用下面独立免费入口，避免改动原历史排队记录。关闭聊天/浏览器后后台服务继续；主动停止后保持停止；异常退出最多按退避重试三次。电脑重启后先恢复 Docker 引擎，再执行 start，不把主机关机当成仍可执行。

1. **从用例到运行：** 在用例库查看 `T17H-WELCOME` 或 `T17H-CONFIRM`，点击“使用此用例新建运行”。核对所选修订，再看版本、故障、种子、次数、预算和时限；点击“检查环境与配置”，确认明确离线标识后再创建。仅在此隔离免费入口操作。
2. **查看结果：** WELCOME 应不预约；CONFIRM 先草稿后确认，实际 SQL 一笔。到运行证据查看工具、SQL 与断言，观察实际来源“离线受控模型”。不要把创建/排队成功当作预约成功。
3. **阻塞与排队：** 查看环境中的真实 Worker/Dispatcher 观察与启停指引。关闭隔离服务时默认创建应阻塞，保留配置；明确选择“仅保存并排队”才保存任务，并显示期限。恢复后只有未过期且条件匹配的任务继续；过期收尾，等待输入另处理。不要用默认 main 脚本去停止隔离入口，请按其 profile 和本地回执确认操作对象。
4. **再次运行：** 在某个开发运行的证据页点击“按原配置再次运行”，核对原修订和参数只读；创建的是新运行，原记录不改。缺源码或模式不同应提示无法按原条件复现，不能偷偷换版本。
5. **复制修改：** 点击“复制并修改”，只改一个种子或其他参数。预检必须列出差异，并保留来源运行/manifest 关联；原输入与历史结果保持。
6. **过期与重复：** 预检有效 60 秒，过期后应重新检查而非继续提交。创建回执不明确时使用“查证原创建回执”，不另建请求。
7. **显示与权限：** 切换深浅主题、手机宽度、键盘操作。没有兼容版本显示原因；特殊知识用例不自动降级为基础规则。其他账号、正式校准/保留样本不能借复制入口进入开发调优。
8. **等待输入：** 使用 `T17H-WAIT` 修订 2；修订 1 因遗漏 DSL 版本保留为无效旧修订，不能用它冒充可运行。运行到等待输入时应只有草稿、0 笔预约；从“处理等待输入”发送“确认”后查看 SQL，最终 1 笔。自动验证已检查相同 request_id 的输入重放仍只有一笔，不需要团队额外拼装 HTTP 请求。
