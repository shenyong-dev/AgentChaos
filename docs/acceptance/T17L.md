# T17L 验收

本项验证平台能否识别明确构造的缺陷。真实与免费接线数据分别保存；不能将构造变体说成当前生产Agent存在这些缺陷。

1. 查看`docs/fixtures/T17L/catalog.json`和执行方案，核对4类缺陷、8次执行、原预期及预算。
2. 完成回答视图独立标注前，不查看真实结果的组别、SQL、激活记录或规则。进入本轮提供的本地私有标注链接，逐条仅按输入与最终回答选择判断，勾选独立声明并封存；未给SQL不能推断为0。没有足够证据可选“信息不足”。
3. 封存后查看本轮结果报告，任选健康、检出、未激活/未知（如有）各一条，在`.local/t17l/real-01/<组>-<侧>/`核对：`started.json`冻结绑定、`activations.json`实际命中、`observations.json`SQL与原事件、`report.json`保存规则及证据引用。没有命中记录不能当激活。
4. 从`summary.json`重算分子/分母；原始真人标签在`human-labels-sealed.json`，映射在`private-unblinding.json`，后续复核不得覆盖原标签。信息不足与实验未知不能删掉后宣称总体准确率。
5. 检查`database-verification.json`的17表恢复哈希、独立预算usage/未知预留和最终保全审计。主环境原版本、`.env`及旧账本不得因本实验被重置；同期人工操作引起的观察变化另列，不回滚。

免费复验只需按架构文档命令使用全新本地输出目录；它会写自有隔离库，使用离线模型，不会发付费请求。真实批次已有限次授权，禁止删除启动标记重跑。无需重启主API、UI或Worker。

本地真实标注页只接收独立标签，不开放模型调用或业务写入；封存不可覆盖。若链接过期，保留原数据后重新开启同一盲包入口，不新跑模型。
