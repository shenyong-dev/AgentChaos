# T17G 用例说明与可理解性验收

本次“开始下一步”确认 T17F 修正并授权 T17G。范围是确定性开发用例说明；完成后交团队检查，T17H/I/E 未开始，无新付费调用或 Git 发布。

## 团队怎么验收

1. 打开 [开发用例库](http://127.0.0.1:5173/library)。使用本地 `demo_operator` 平台身份登录，密码读取本地 `.env` 的 `DEMO_SEED_PASSWORD`；不在文档或截图中复制密码。已登录可直接切换板块。
2. 先看列表中人类可读的测试目的、类别风险、修订和知识条件。搜索仍按用例编号，点击“查看用例”。
3. 随机选三个不同类型，只看页面，分别说出“为什么测、前置条件、每轮发什么、允许什么结果、用什么证据判定”。可参考下表，但团队不必照选这三条。
4. 展开每条原始断言及底部高级信息，对照其参数、修订与 `content_hash`。例如“至少存在一条”不能被解释成“只有一条”；只调用检索不能当作检索正确。
5. 切换深浅主题，使用手机宽度，滚动长对话至末轮；输入、关闭按钮应可读可点，无遮挡或页面横向溢出。
6. 仅核对运行入口时，关闭说明、勾选基础知识用例、点“新建运行”查看现有配置即可；不必提交。日常付费开关关闭且没有主 Worker，排队不代表真正执行。本项不需要重新运行冻结实验。

| 示例 | 页面应讲清的内容 |
