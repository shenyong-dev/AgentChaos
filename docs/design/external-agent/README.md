# 外部 Agent 标准接入方案

2026-11-16 · P06-A · 协议与接线设计 v0.1

目标是：外部开发者实现一次适配服务，管理员登记后，用户在现有工作台选择对象并运行测试。适配相同协议的新对象应主要增加配置、用例和领域规则，不再复制一套执行器。

**基础对话接入已实现。** 服务端配置、接口示例、工作台操作见[接入手册](runtime/README.md)。本文保留 A 阶段的整体设计。

## 1. 接入分为两层

| 层次 | 外部提供什么 | 平台能验证什么 |
|---|---|---|
| 基础对话 | 能力卡、消息发送、任务查询、鉴权；声明是否支持取消 | 输入输出、任务状态、超时、可观察的交互行为 |
| 业务验证扩展 | 测试范围隔离、原请求键查证、事实快照、可选工具/检索事件 | 已声明领域的副作用、幂等性、授权与故障表现 |

只有对话的Agent也可按第一层接入；业务事实、内部工具轨迹和检索指标按实际能力显示不适用。回答“已经完成”只作为模型输出保存，不能替代数据库或独立事实源。

通信层优先复用[A2A官方规范](https://a2a-protocol.org/latest/specification/)的能力发现、消息、任务查询及取消。正式实现须固定发布版本、SDK及测试向量，不能在运行中跟随`latest`自动变化；当前未选择SDK或宣称A2A兼容。已有普通HTTP接口可由薄封装转换为统一入口，LangGraph、Dify、Coze等框架不作为平台执行器依赖，也不宣称它们当前都原生兼容。

A2A的消息发送幂等性是可选的，取消任务也不保证成功。因此，测试业务写入还须实现本项目的键绑定、未知查证和事实扩展。这些是AgentChaos要求，不能写成A2A本身已经保证。官方依据：同规范3.3.1、3.1.5。

## 2. 一次接入的实际流程

1. 开发者启动独立适配服务，提供能力卡和必要接口，声明来源、版本、支持范围、鉴权及隔离方式。
2. 管理员在服务端登记固定地址、协议版本、允许的能力与凭据引用。用户只能选择已登记的对象ID；创建运行的请求不接受URL、代码、动态导入路径或密钥。
3. 先执行只读连通、版本与能力检查；可能产生写入的自检须显式进入全新测试范围，先冻结检查项目和预期。
4. 自检通过后追加不可变对象版本，绑定能力卡、协议、连接器、规则、用例和来源哈希；登记本身不运行模型或创建业务执行。
5. 用户沿原工作台预检、创建、运行、查证据和导出。没有提供的能力明确不适用，协议或来源漂移时拒绝新执行，保留旧证据。

接入完成后，相同协议的基础对话对象原则上只需登记配置和用例。要新增专有业务规则或进程内故障点，仍需审核对应扩展；不能承诺任意Agent完全零代码接入。

## 3. 统一执行端口与责任边界

| 端口 | 输入或绑定 | 必须遵守的行为 |
|---|---|---|
| manifest | 已登记对象ID、固定版本 | 声明能力、输入输出类型、限额、来源及端点版本；不授予权限 |
| prepare | 可信owner、run/execution、全新scope、fixture版本 | 只准备授权测试环境；重复调用校验原绑定，不能清空已有事实 |
| execute / send | 原request_id、输入哈希、上下文版本、截止时间 | 相同键和正文复用原结果；同键不同正文冲突；平台超时不改键重发 |
| lookup / task.get | 可信绑定及原request_id，已知时附task_id | 即使发送回执丢失、尚无task_id，也能定位原调用；找不到不等于未执行 |
| snapshot | 可信绑定、快照时刻/修订 | 区分可验证空集合、缺失、未知、不适用；附来源和完整性信息 |
| cancel | 原调用/任务、可信绑定、取消请求键 | 只请求停止，区分已请求、已确认、已结束/不可取消；不撤销已提交副作用 |
| evaluate | 原断言、完整证据和领域规则版本 | 运行平台侧审核规则；缺事实不判成功，不接受外部自行宣称“通过”替代判定 |

外部输入始终是非可信数据。租约、预算、owner/scope授权和最终状态仍归平台控制；远端服务不能修改平台root、放宽限额、选择新的工具权限或直接提交最终评分。

Agent报告的工具事件、token用量及业务事实须标注`external_reported`。平台亲自拦截/读取的证据才标`platform_observed`；能力卡、哈希或TLS只能证明来源/传输对应关系，不能证明所报告业务为真。高可信业务结论需独立只读事实源或测试侧代理观察。无法拦截内部工具时，F02/F04等内部故障明确不适用，不能用HTTP断线冒充提交后故障。

## 4. 平台侧需要修改的具体位置

| 位置 | 现状 | 实施目标 |
|---|---|---|
| `app/adapters` | RefundAdapter仅manifest/prepare/snapshot，预约保留原生支路 | 服务端固定registry和统一能力描述；外部对象共用一个HTTP连接器 |
| `app/executors/runner.py` | 预约完整任务和退款内层端口形状不同 | 先保留外层claim/预算/租约/finish，再统一内层execute；避免双重claim或重复finish |
| `app/executors/service.py` | 创建、fixture和快照包含领域分支 | 基于已登记能力、用例Schema和事实接口分派，保留owner/版本/用例审核/防重 |
| `app/evaluation/service.py` | 预约和退款规则独立分支 | 注册平台侧规则及输入Schema；通用回答检查与专有业务规则分开 |
| `app/workbench`、版本登记 | 两种对象白名单 | 读服务端registry，不允许客户端自填适配器或新端点 |
| 报告、可靠性、裁判、用例冻结 | 多处预约语义和退款N/A分支 | 按明确能力决定可用项；现有裁判30条校准及原授权继续执行 |

不以修改上述几个入口就宣称所有域分支消失。用例DSL、故障工具、报告字段和交互调试同样需要逐项适配。

## 5. 网络与调用约束

服务端登记固定origin及路径前缀；能力卡中出现的其他URL不能自动跟随。运行前校验登记来源和地址策略；公网目标拒绝内网、loopback、link-local和元数据地址，内网目标须单独审核并通过受控出口/固定解析约束，避免DNS重绑定。重定向、环境代理、回调和服务端抓取任意附件默认关闭。凭据来自独立secret引用，不进入能力卡、运行清单、页面、导出或日志。

请求使用现有超时、取消、输出大小、并发和费用守卫；HTTP限时不证明远端已经停止。协议还须声明远端的最大调用/费用上限及凭据范围；只拿外部token自报不能声称由平台完整计量。未知请求保留原键、预留和原正文哈希，先查证，不能自动重试写入。重启后从持久intent/回执恢复；丢失绑定时停查，不重建额度或假装新任务。

## 6. 自检及完成门槛

基础自检应覆盖：鉴权失败、版本不符、超长/非法响应、超时、重复请求、同键改正文、多轮关联、跨owner/scope隔离、请求回执丢失时按原键查证、取消竞争、重启后查证及来源漂移。业务扩展另查零事实/缺事实、确认后修改、重复副作用、独立事实来源、原事件完整性。每次自检使用新目录和新scope，冻结检查集后记录首次结果。

先用预约/退款核对契约，再用项目自编的隔离HTTP替身验证连接器。最后须有其他开发者提供的对象完成实接，记录新增文件、接线改动、故障和计时。自编HTTP替身只能证明工程协议，不是独立外部验证。

| 阶段 | 本轮状态 | 完成依据 |
|---|---|---|
| P06-A 契约、原对象清单、接入模板 | 已落地离线检查工具 | 严格结构、原源码符号及参数核对；不是运行行为认证 |
| P06-B 固定版本HTTP连接器与本地替身 | 基础对话已实现 | 原键防重/未知持久化、地址约束、限额/故障控制 |
| P06-C 实际平台接线 | 基础对话已实现 | 工作台登记与选择、执行/证据/报告、原预约和退款回归 |
| P06-D 独立开发者对象 | 待提供并验证 | 真实接入记录和完整控制结果，不以项目自编对象替代 |

## 7. 现有清单与离线检查

[预约清单](profiles/booking.json)、[退款清单](profiles/refund.json)、[外部填写模板](profiles/external-template.json)采用相同的草稿结构，附[结构Schema](profile.schema.json)。Schema校验基础字段，检查器另核跨字段关系和实际源码。它们是清单文件，不是生产manifest、可执行插件或管理员注册配置；`network_enabled`固定false，检查输出固定`registration_ready=false`。

在`D:\AgentChaos\backend`运行：

```powershell
.venv/Scripts/python.exe -m benchmarks.adapter_contract.check --output ../.local/p06-contract-20261116-r1/source-inventory.json
```

输出必须是不存在的新文件，父目录须已存在。检查器不导入应用、不读取`.env`、不连接数据库/Redis、不执行清单中函数、不访问网络；只核对结构和源码符号/参数并记录SHA。源码相符不证明权限、取消、幂等或业务事实正确。自检通过也不自动登记或启动试验。

当前旧预约/退款生产代码及原冻结版本保持。后续生产实现涉及来源变更时，须正常追加新版本，不能把新连接器塞进旧manifest后重开历史运行。
