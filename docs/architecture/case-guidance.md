# 开发用例阅读说明（T17G）

说明只属于展示层，不送入被测 Agent，不参与评分、不修改 DSL 或已审核预期。

## 数据来源与绑定

- 复用 `/api/v1/workbench/cases` 和 `/cases/{id}` 的身份与可见性限制：只提供最新已审核开发修订；T13 还须属于当前冻结清单。校准集、保留集及未审核样本不经此入口公开。
- 详情先执行原有 `frozen_case` 内容哈希和 DSL 校验，再派生 `guidance`。列表校验失败时显示 `unavailable`，不生成貌似可靠的目的说明。
- `title/reviewed_reason` 摘自该修订夹具中的 `dataset.independent_expectation.reason`；没有理由时明确标待补充。`turns`、原断言参数、业务目标、允许数量/预约事实和人工检查项保留原值。
- 风险关注、断言解释、运行说明由固定代码产生；逐轮对照提示由前端固定模板产生，不推断对话中的最终字段值。它们不是新增独立真人标注，也不证明实际执行已通过。
- `case_revision_id/revision/content_hash` 绑定原用例；`policy/policy_hash` 绑定解释代码（LF 规范化 SHA256）；`guide_hash` 是上述完整说明的独立规范化哈希。原 `content`、`dsl` 和 `content_hash` 不变。
- 缺审核理由或初始状态为 `partial`，原始内容不可验证为 `unavailable`。说明缺项不能补猜目标、SQL 数量或通过结论。特殊知识条件继续由原运行契约限制。

## 返回结构

列表每项增加 `guidance: {title, risk, status, policy, guide_hash}`；无法校验时只返回待核对说明与状态。详情在原响应旁增加 `guidance`：

| 字段 | 作用 |
| --- | --- |
| `prerequisites` | 夹具、参考时钟、知识条件、声明的初始状态；故障需另选且核对真实触发 |
| `turns` | 完整逐轮用户原文，仅增加轮号 |
| `expected` | 原业务目标、允许数量和事实、人工核对项；明确目标与规则遵从分开 |
| `assertions` | 当前 11 类断言的含义、证据类型和原始参数 |
| `run_steps` | 工程环境 → 勾选用例 → 原有新建运行 → 原始证据；不自动创建或付费调用 |
| `missing/provenance` | 缺项和说明来源 |
| 修订/策略/说明哈希 | 与原始内容及说明代码分开绑定 |

响应仍用已有 `Envelope[dict]`，没有新端点或请求字段；原 19 份 OpenAPI/Schema 契约需内存重导出核对。无数据库迁移、依赖或新权限。

## 判定边界

1. `booking_count` 检查 SQL 后快照有效预约的精确数量；`booking_matches` 只检查至少存在一条符合声明字段的预约，不保证唯一或未声明的时间。
2. `tool_calls` 检查请求次数和参数，扣除有证据的同回执重放；被拒绝的请求仍计入。调用过检索工具不代表检索正确。
3. 确认绑定检查真实输入、当前草稿和请求标识；没有提交请求时不适用。未知提交未完成原键查证闭环为证据不足。
4. 结构化状态、结构化业务声明、字面回复和 SQL 是不同证据，不能互相替代；自然语言通用语义仍需人工判断。
5. 缺少 SQL 不等于 0 条；允许安全降级为 0 或 1 条时不强称必须成功。故障类别本身不注入故障。

输入始终用 Vue 文本插值展示，不能执行 HTML 或提升权限。快速切换用例时只接受最后一次详情请求，账号/页面代次保护继续沿用 T17F。

## 当前覆盖与限制

只读覆盖清单见 `docs/evidence/T17G/coverage.json`：60 条开发用例、六类，56 条基础知识条件匹配，4 条需对应知识环境。六类原始来源示例见同目录 `six-development-examples.json`。

本项不提供 T17H 的分步创建/复现，不提供 T17E 的生成式解释，不把开发者浏览器自测当首次使用者验收或新模型能力成绩。
