# 可靠性结果投影（T17J）

`GET /api/v1/runs/{run_id}/reliability` 通过现有平台身份和运行归属读取数据。接口使用同一非锁定数据库快照；不创建运行、断言、报告、预算或模型请求。

摘要读取该运行全部执行与保存断言，复用 `load_evidence` 校验事件、工具配对、证据文件和SQL快照。保存规则的 `input_hash` 必须与当前证据及冻结DSL一致；不一致时保留原规则，展示证据不足并排除通过分母。运行清单或对象配置不匹配时返回读取错误。最多600执行、50000事件、120000保存判定；超限拒绝摘要，不把部分记录当完整统计。

运行状态单列。统计按实际gateway来源、冻结数据分区及最新规则的评价器代码版本分组；不汇总不同来源的成绩。每组原样复用T15的 `statistics`：有效规则通过数/(通过+未通过)，业务达成数/(达成+未达成)。等待、取消、跳过、平台异常、证据不足、评价错误和未评价分别保留；安全降级不计作目标达成或失败。重复执行不等于独立家族。

六个维度只整理已有规则：工具契约、确认绑定、参数/字段、预约唯一性、未知提交原键查证、业务声明与事实。维度样本单位为执行；同一执行可重叠。没有真实工具请求、确认活动或有效预约时，不用相应通用守卫的通过宣称覆盖；工具调用次数为0或没有参数条件的断言不证明参数一致性。不适用且没有其他适用规则时显示未测试。维度不构成综合分，也不证明通用权限、通用语义或全部异常恢复能力。

故障配置与实际事件分别展示。只有有效 `fault.injected` 事件证明实际注入；配置存在且完整执行无注入时为未触发，记录不完整时为尚不能确认。SQL缺失或结构无效为未知，合法空列表才为0笔。任务结论仅在完整且指纹匹配的已结束执行上展示，其余为未知；原保存结论仍可在断言页核对。

运行详情默认进入结果概览。摘要不依赖前端事件窗口或500条显示上限。按钮进入原链路、指定执行/评价版本/断言、SQL快照与AI记录；读取和导航不自动评价。页面请求按运行、身份和读取代次隔离，刷新失败撤下旧摘要。原报告、T16无改善结果、T17B受限辅助边界和历史标签不变。
