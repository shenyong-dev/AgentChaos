# 环境就绪与首次使用引导（T17C）

常规检查只提供免费观察。`GET /api/v1/system/readiness`返回`T17C-1`，单项状态为`ready / blocked / unknown / not_available`，包括观察时间、60秒有效期、阻塞码、说明及下一步。响应使用`Cache-Control: no-store`，仅返回允许公开的布尔值和计数，不返回密码、密钥、连接串、数据库名或Worker主机名。

| 操作 | 前置条件 | 附加边界 |
| --- | --- | --- |
| 查看历史与证据 | API、MySQL、必要表与迁移 | 无需Redis、模型开关或Worker；实际数据仍按登录账号权限读取 |
| 准备离线验证 | 以上，加Redis、JSON/Search、兼容源码版本 | 仅提示独立离线验证脚本的准备条件，未执行或声称已完成演示 |
| 现有交互API | 以上，加凭据存在、交互角色授权/开关/账本 | 不代替合法会话、草稿、确认和实际逐次预留；可视化窗口留待T17D |
| 批量真实测试 | 同上，但使用批量角色预算，另需匹配Worker | 不创建或投递运行，不变更已有排队执行 |
| AI用例生成 | API、MySQL/迁移、Redis、凭据、生成角色开关与账本 | 候选仍需人工审核 |
| AI辅助裁判 | API、MySQL/迁移、Redis、凭据、裁判角色开关与账本 | 所选批次的真人先封存等守卫仍在实际动作核验；T17B继续仅人工辅助 |
| 平台AI助手 | 尚未实现 | 明确显示尚未提供，留待T17E |

数据库探针仅读取当前迁移、必要表及`RunService.current_manifest()`对应的可用对象版本，不执行迁移、自动登记或切换历史版本。凭据检查仅表示存在，没有验证实时模型连接。历史模型成功记录保留独立标签，不计入当前基础连接健康数量。

Worker使用Celery只读自定义`inspect_command`取得实时回执，核对启动时源码指纹、实际MySQL实例/库/命名空间绑定、执行配置及实际消费队列。指纹覆盖Python、Prompt、迁移源码和锁文件；不含密钥。数据库绑定使用服务端UUID与实际数据库名计算，避免仅比较不同网络地址造成误报。未收到回执时为未知，不能证明Worker停止，也不能由配置推断存活；收到不匹配回执则阻塞。旧Worker未载入该命令时也不会显示绿色。该远程检查只经现有命名空间控制通道发查询，不派发执行任务、不增加消费者或启动服务。实现依据：[Celery官方自定义远程检查命令](https://docs.celeryq.dev/en/stable/userguide/workers.html#writing-your-own-remote-control-commands)。本项实测Windows solo控制通道，未把它当作Linux prefork平台可靠性的重新验收。

预算探针仅读取已开启且授权匹配的角色账本，缺失、耗尽、协议异常或读取失败分别显示阻塞/未知。未知请求的预留仍占余额。未开启角色直接显示关闭，不因历史授权无总金额上限推定本项获准。探针不初始化、清零、预留、退费或调用模型；余额大于零也不能替代实际输入大小、每run/批次和逐次上界预留。角色配置及账本读取是提示，真正动作仍由原服务端守卫决定。

前端在刷新期间撤下可用标签，过期或刷新失败后将旧结果标为历史；无结果不填绿色。每项可展开原因、下一步和检测依据。首次使用四步指南随前端版本提供，API断开仍可阅读；这不表示未缓存网页时能脱离前端服务器访问。检查按钮不会安装软件、启动服务、修改`.env`或全局数据库配置。

本项验证使用独立MySQL库、只读SQL/HTTP、无模型密钥、专用命名空间和队列。临时无模块Redis仅复用已有D盘运行程序，单独端口/数据目录，已停止；共享Redis没有被中断。恢复既有D盘Redis脚本属于开发准备，不是检查端点的自动修复能力。T16冻结实验和T17B原标签、AI与统计继续保留。
