# T12 语义辅助评价与独立校准

采用自定义、严格结构化的语义评价器，沿用已有DeepSeek适配层、FastAPI和Vue3/Element Plus，不新增评测框架依赖。范围是回答支持性与解释合理性；预约参数、SQL副作用、确认权限、幂等和任务达成仍由客观规则检查。

## 三类结论

- `rule`：现有独立规则、业务快照、工具和状态检查。
- `ai`：回答支持性与解释的辅助意见，带理由、引用、模型配置、输入/输出、usage及错误。
- `human`：校准前独立标签，以及看到分歧后的另存复核。前者不能被后者或AI结果回填。

AI通过不会修改execution状态、规则判定、任务达成、预约事实或Agent上下文。实际执行的AI与人工复核分别追加`ac_assertion_results`的ai/human来源；规则版本列表只列rule，避免新来源混入原规则下拉列表。旧规则结果、事件和判定不覆盖。未添加新的规则谓词。

## 输入边界与结构化输出

每次只向judge发送固定系统评价说明，以及一份允许字段组成的观察数据：选定用户输入、待评回答、SQL后快照、字段/确认状态、实际检索结果与适用资料。状态抽取不等于SQL写入。若对话超过6轮，只提供前3轮和末轮，明确标为节选，不推断未给出的轮次。

不发送人工标签/标签哈希、规则passed/failed、用例expected、来源是否受控、Agent Prompt、检查点、旧裁判结果、私有推理或其他会话。模型没有工具权限，资料与待评回答中的指令均为数据。真实请求逐条与允许的payload核对；不能仅凭提示词声称没有标签泄漏。

支持性为supported/contradicted/insufficient；解释为reasonable/unreasonable/insufficient。结果必须包含两维标签、模型自报把握、可核对理由、存在的证据引用、总意见与复核标记。0.8是预先声明的自报把握门槛，**不是已校准概率**。低把握、缺证据进入inconclusive；缺字段、JSON无效、引用不存在、结论与结构化维度矛盾或服务失败为error，均不能自动通过。根因说明只标候选。

## 校准流程

`docs/fixtures/T12/samples.json`冻结30条相关样本、10个来源家族：10条历史真实Agent回复，另20条明确受控的回答修改/证据移除。保留原导出路径和SHA256，不把衍生反例计成自然缺陷、30个独立家族或正式保留集。

1. operator建立固定数据集批次；接口不接受客户端标签或任意Prompt。
2. reviewer逐条自行选择两维标签，未预填建议值；自由说明可选，无说明时如实记录未补充。真实身份和时间由认证与服务端提供。
3. 30条齐全后，reviewer声明在未见本批AI结果时完成标注并封存。此后禁止改写原标签。
4. 首次评价前冻结最终实现源码、Prompt/模型/Schema/阈值。只允许实现整理，不得悄悄改变标注前的评价定义；调用开始后版本不匹配必须停止，不能同批混用版本。
5. 每条独立请求，持久化尝试后调用一次；不隐式重试。中断留有started时不自动再次付费。读取历史、重复请求和刷新不调用模型。
6. 对不确定、服务错误、人与AI分歧排队复核；reviewer另存最终两维意见和必填依据。原独立标签/AI保留，统计仍用校准前标签，不能用复核回填提高一致率。

报告分别给两维混淆矩阵、一致率、Cohen kappa、有效评分覆盖、裁判失败率、误接受/误拒绝列表；原回复/受控回答/删证据分层报告。首版是一个实际标注账号与同服务judge的比较，不宣称双人独立标注、跨模型客观金标准、无同源偏差、保留集准确率或统计显著。

## 执行记录接入

`/api/v1/judging/executions/{uuid}`提供独立读取/显式评价；需要同版本30条校准及分歧复核完成。只接受完整封存的执行，知识修订必须与当时manifest及正文哈希一致；缺少资料/证据不会补造为0或通过。模型只得到实际观察，校准批次和标签只留服务端审计。

已有运行的“AI辅助评价”页只读加载，调用必须显式操作并受独立开关限制；另有reviewer复核页。AI/human记录追加保存，原rule与业务状态不改。此接入可用明确离线控制验证平台行为，不能据此声称进行了新的真实Agent实验。
