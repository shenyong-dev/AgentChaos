# T17B 裁判协议 v2

状态：2026-10-30实施及新校准完成，用户确认保留为受限人工辅助。12/12结构有效，原人工一致率50%/58.33%，7条分歧保留。旧T12/T16协议及全部结果保留。本协议不改变规则评价、预约事实或人工决定。

## 真实缺陷与修复

原90次T16响应中66次不满足旧响应模型：19次把两个维度写成字符串；41次支持性引用为空、28次解释引用为空；另6次为无效JSON。各字段错误数有重叠，不能相加作失败分母。逐次原文件SHA及分类见`docs/evidence/T17B/legacy-diagnosis.json`，未重算旧实验统计。

原提示包含枚举管线写法和不一致的占位值，也没有在实际请求中提供完整响应Schema；这是对协议缺陷的分析，不是单独验证过的因果归因。

- Prompt换成两个完整、可被当前解析器接受的JSON例子；枚举与结构以实际Pydantic `JudgmentV2`生成的Schema为准，随请求附上。
- `protocol.messages`只发送实际dialogue/reply/dialogue_scope/evidence，明确answer_only或observations；不发送来源类型、人工标签、旧规则结论或期待结果。输入包由同一函数用于校准与执行评价。
- Gateway仅judge角色启用`response_format={"type":"json_object"}`，记录实际模式。Agent和生成器的调用路径不启用此参数。SDK `max_retries=0`。
- JSON解析拒绝重复键、非有限常量、Markdown或尾随文本；不补括号、不拆字符串、不强制转换扁平响应。空白、截断、坏结构和服务错误保留为error，usage已获得时照常结算。
- 非insufficient维度必须有非空、无重复且实际存在的引用。insufficient允许空数组，但reason需说明缺口。null证据不算可引用事实；SQL空集合与未提供SQL分开。未知引用或不一致结论不是合法弃权。
- insufficient、低于0.8自报把握或主动复核时，必须同时返回`needs_review=true`和`conclusion=uncertain`。服务端检查，不替模型悄悄修正。

官方[JSON Output说明](https://api-docs.deepseek.com/guides/json_mode/)于2026-10-30核对，提示JSON模式仍可能返回空白。JSON模式不验证本项目的嵌套Schema或事实正确性，本项目继续严格校验。当前[定价](https://api-docs.deepseek.com/quick_start/pricing/)峰值输入未命中0.30/输出1.20美元每百万token与已有保守估算一致；usage估算不是账单。

## 版本与兼容

旧`Judgment`和`semantic-judgment.schema.json`不改，旧Artifact不重新解释。`JudgmentV2`及`semantic-judgment-v2.schema.json`增加合法证据不足的空引用分支；其余顶层结构兼容界面。新结果标T17B-v2，manifest冻结Prompt、Schema、解析器等源码和Gateway哈希。封存与真实调用前都要求与初始manifest完全一致。

旧30条校准读取和统计继续支持，标注页改为按冻结数据集显示实际条数，T16三维金标准仍保持三维。API新建校准默认T17B的12条；内部旧脚本仍可显式载入T12。原有“执行级辅助评价需30条同版本校准及分歧复核”的守卫保留；本12条小校准不自动开放批量执行评价，不以新协议默许使用旧付费授权。

## 本批实验边界

12条新编受控开发例，6条回答视图、6条附观察，非真实Agent输出，也非正式保留集。无标准答案字段、无预填或助手建议。真实用户逐项标注后先封存，再发送相同观察给裁判。模型看不到真人标签；辅助复核若需要另存，不覆盖原标签或裁判结果。

独立T17B judge授权最多0.50美元/12请求，输出1536token/次、45秒/次；输入32768字节、每批100万token及0.50美元上界，跨批次仍共12请求。无修复、无自动重试，因此初次/最终结构有效率相同。unknown保留预留，不退款式清空。旧12份授权逐字段不变。

标注HTTP进程没有模型密钥、付费开关或Worker，仅允许当前批次的label/seal写入。付费监督进程需要独立人工封存与显式本地启动信号；常规GET/刷新不会调用模型。只清本项自有临时库/用户/子进程，保留ZIP、源码与账本。
