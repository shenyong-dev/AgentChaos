# T11 候选生成、独立检查与人工修订

本功能只处理自建预约实验的3类开发模板：完整预约、固定A101容量越界、多轮修改。技术栈沿用FastAPI、Vue3/Element Plus、MySQL和Redis，没有新增依赖。它不代替T13数据集冻结，也不生成保留集成绩。

## 生成和预算

`POST /api/v1/case-generation`要求operator认证，只接收UUID请求标识和1—3个预置profile。批次UUID同时是幂等标识；同请求内容重放读取原记录，配置变化返回409。进程中断后保留incomplete，不擅自重新付费。API同步执行，页面等待上限110秒；这里没有宣称新增后台Worker。

生成器使用独立`case_generator`配置、Prompt、原始流式调用、usage和全局Redis账本。当前T11授权标识`T11-20261028-casegen-open`，金额总额不限；每批仍限制2次调用（包括最多1次格式修复）、200000 token、0.10美元保守占用和90秒。调用前先持久化预算票据；缺失全局账本拒绝调用，未知usage保留占用，不能重新初始化获得额度。根目录日常三个付费开关均关闭；专用审核环境可在既有T11授权下启用生成器，agent/judge保持关闭。

只把受版本管理的公开实验规则文件、独立编写的风险条件、参考时钟和Candidate Schema发给模型。Prompt构造不查询任何用例表，也不把独立expected_count作为答案标签提供。开发候选仅用于查重；该查询严格限制dev，不读取holdout文本或答案。原始request manifest冻结完整公开输入、模型配置、Prompt/规则/源码/Schema哈希，后续代码修订不会改变旧批次输入。

## 检查与修订

空输出、截断、JSON不合法和批次结构错误分别记录，最多一次完整格式修复且计费。单条Schema无效候选保留原始值和错误位置，不创建用例修订。有效JSON中的错误预期不会自动改正。

独立规则检查预约数量、日期/人数/场地、任务目标、互相矛盾的断言和现有执行器的最后确认词。文本做NFKC/大小写/标点归一；语义指纹来自公开模板、条件和参考日期。同条件的不同措辞也算同类开发候选，不能充当新的独立测试家族。检查器不能完整理解自然语言，所有通过仍要求人工审核。

初次检查写入不可变artifact。读取时另返回`recheck`及当前检查器哈希，反映早期候选被拒绝后释放的重复约束；初次valid_rate和状态不随复检改变。不能把复检结果、人工修改后的结果回填成原模型有效率。

`POST /api/v1/case-generation/candidates/{id}/review`只允许reviewer，候选哈希绑定实际原文。批准或修改后批准追加新`ac_test_cases`修订；原始草稿/候选和人工说明保留。拒绝不创建已批准版本。审核请求UUID幂等，已有决定不可覆盖。审核在共享`case-family:`锁下检查重复和跨分区家族。`approved`、reviewer身份、分区、家族、修订号不能由模型或导入JSON声明。执行器仍拒绝draft/rejected，接受批准修订时冻结内容和审核人。

页面主区展示批准后的修订，对话、断言与独立条件并排；原始JSON、初次检查、当前复检、Schema错误及内容哈希可展开。凭据只保存在页面内存；刷新须重新登录。另一operator批次/证据返回404，reviewer可团队审核；不是生产租户管理。

## 存储与兼容

迁移`20261028_0004`只调整`ac_artifacts`：run_id可空，新增owner_id外键与索引，并用CHECK约束run/owner归属互斥。仅4种生成/审核kind可以不关联run，不伪造Agent运行。仍为16张业务表、23个保护触发器；旧run artifact归属、事件1.0—1.3和历史审核结论保留。证据文件在D盘项目`.local/case-generation`下，API按批次拥有者、路径边界、大小和SHA256验证。

已存在owner证据时回退迁移明确拒绝，不隐式删除成果。`verify_case_generation.py --replay <replay-records.json> --review`从公开导出文件重建隔离库：原字节/候选哈希/审核身份/修订保持，实际文件重新映射到本地目录；不是新模型调用。加`--enable-generation`才为人工真实生成开放既有T11预算。停止文件和自动到期清理本次进程、专用SQL用户及隔离库，全局预算不删除。

## 当前证据边界

两批最初真实输出使用原Prompt/检查器，发现确认词与不合理禁词断言后保留失败，由用户确认7条具体决定后执行。新增确认词检查和Prompt说明尚未再次付费生成，不能声称提升后的模型有效率。离线错误预期控制、空输出/截断和UI无效值桩都明确标记，不计自然模型质量。首轮恢复脚本日期反序列化错误及首轮UI遗漏Schema错误详情均保留，修复后复验。详情和实际指标见`docs/acceptance/T11.md`。
