# T17L 已知缺陷检出验证

本项是平台效果的开发实验，不是第五种业务场景，也不替代T16的V0/V1结果。入口为`backend/benchmarks/t17l`的显式CLI，应用与Worker不会导入实验变体。

## 分层

| 层 | 依据与限制 |
|---|---|
| 冻结目录 | `docs/fixtures/T17L/catalog.json`给出4组输入、顺序、原预期和激活判据；8次执行分别创建初态相同的test scope |
| 被测变体 | 实验客户端/字段来源校验的局部hook；manifest包含目录、实验源码、原评价器指纹及组别。内部客户端的额外写入单独记变体日志，不伪造成模型工具调用 |
| 事实采集与规则 | 原`backend/app`字节保持；SQL、模型和工具事件、规则及报告导出沿用现有实现，不针对变体改评分 |
| 外部事实oracle | 直接读隔离SQL核对数量、日期、时段、人数、场地，并结合实际激活日志；不从规则结论反推真值 |
| 回答视图 | 同一执行的实际输入和最终回答，随机Q编号，无组别、预期、SQL或规则答案；真人独立封存后才揭示映射 |

未确认写入由preview后的客户端误提交构造；负数由弱子串校验构造；重复写入同时包含换新请求重试及隔离占位保护缺陷，明确为多层变体；虚报成功由确认客户端返回结构化成功但不写SQL构造。最终自然语言仍是模型真实输出，不能称模型自行产生了这些代码缺陷。

## 隔离及运行

程序只允许生成的`agentchaos_t17l_verify_<12位hex>`库和`ac:t17l:<marker>`命名空间。实验账号只获自有库及其恢复库的权限；迁移触发器、归档恢复需本机管理员权限时，连接仍限于严格生成的自有库。不改全局MySQL配置，不给实验账号SUPER。

免费模式使用明确的OfflineGateway验证工具接线，不能算模型效果。真实模式不传`gateway_factory`，执行器保留`real_provider`标识，使用T17L预算实现，原预留、结算、未知保留与SQL票据镜像复用。模型探测历史文件不因实验更新。

```powershell
$env:PYTHONPATH='D:\AgentChaos\backend'
backend/.venv/Scripts/python.exe -m benchmarks.t17l.runner --output D:/AgentChaos/.local/t17l/team-free-01
```

免费命令也会创建隔离库并运行构造变体。不要对主库直接调用hook。真实模式另需与冻结指纹匹配的本地授权文件；`.local/t17l/real-started.json`以独占创建拒绝重复付费批次，失败不会自动重跑。不得删除该文件绕过限制。

## 预算与保全

独立授权`T17L-20261106-agent-1`：总1000000微美元/120请求，每执行100000微美元/20请求；输出1024token，请求45秒，轮120秒，执行300秒。Redis总账本为`ac:t17l:budget:T17L-20261106-agent-1:agent`，原子首次建立，已存在不重置；缺账本、未知用量、超额、输入过大均停止发请求。judge、生成器及助手不调用。

SQL归档是本地`database-statements.json`：JSON数组保留每条原生MySQL语句边界，避免错误拆分触发器。恢复到严格命名的自有恢复库，核对全部17表行数/哈希成功后，才清理本轮自有数据库和用户。异常数据库保留；旧实验和共享日志备份不删除。报告ZIP使用平台原校验清单；原始SQL、模型日志、ZIP及盲标注私有映射仅在本地保留。

## 统计口径

- 检出分母仅含已激活、客观违规且完成脚本/证据可判定的缺陷执行；相关失败规则必须附可定位证据。只有其他规则报错不算该缺陷检出。
- 未激活、证据不足、模型/平台/限额错误、脚本未完成分别保留，不算通过或检出。健康代码出现真实目标失败单列自然失败。
- 健康控制的真值范围为冻结SQL数量/字段。SQL正确但非数量规则报错可能是被拦截的真实违规请求，先列未知待独立复核，不能直接算误报；不能将本小样本比例宣传为所有规则的误报率。
- 回答视图保留“信息不足”及未能判定的比例；只在有明确标签的可比项上计算一致数/分母。它不是裁判准确率，不绕过原30条校准和受限辅助边界。
- 计时为变体观察到规则落库的服务端墙钟差及执行/报告总耗时；真人页加载至封存包含空闲，均不能冒充人工定位耗时。

4类构造缺陷、各1次健康/变体真实执行，不支持统计显著、通用准确率、首次创新或V1整体改善的结论。原T16、T17B及历史标签不变。
