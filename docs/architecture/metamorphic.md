# T10 语义关系与自动对照

在既有 FastAPI、Vue3/Element Plus、LangGraph、MySQL、Redis 上实现；领域表保持16张。目录有12组关系、13个成员，全部同属1个开发家族。共享原句只执行一次，不能按12个独立家族统计泛化效果。

## 输入与人工审核

`docs/fixtures/T10/relations.json` 是调用前提出的显式预期。类型化目录约束成员引用、唯一键、完整条件、等价/改变分类及准确的应变字段集合；条件改变不能套用等价标签。`human-review.json` 记录用户本轮明确确认及规范化目录SHA256。语义审核和最终团队验收分别记录。

本项提供受信任本地验收脚本的目录登记，不提供外部文件上传或任意JSON自带`approved`的审核接口。登记验证回执绑定、按家族持有MySQL advisory lock，检查同家族已审核用例分区，再在一个事务内登记全部成员。已有DB触发器继续保护家族分区与审核角色。它只登记本轮已人工确认的开发目录；T11的候选生成、审核工作流与T13正式分区仍待后续实施。

已有`ac_test_cases.fixture_json`保存完整目录与回执，既有内容哈希覆盖它们。创建运行要求13个成员齐全、目录/回执/原句/家族/分区/夹具/参考时钟一致；清单冻结目录、成员修订及比较器代码版本。每个成员都有独立scope/session/预约夹具；相同参考时钟、知识与模型配置、无故障、seed和重复号用于比较。seed不代表服务商采样完全确定，底层模型别名版本不可独立固定。

## 比较方法

认证 `GET /api/v1/runs/{run_id}/relations` 读取拥有者的冻结运行。核对运行/输入/事件/artifact哈希，通过T08证据加载器展开大payload，再独立投影为日期、开始、结束、人数和场地。

- 字段：读取最终结构化来源值；明确时长独立换算结束时间，允许60分钟和显式15:00的存储形式不同。
- 工具：可预约成员必须真实查询，所有查询/预览参数分别符合该成员预期；可预约成员应有确认提交，容量越界成员不得请求提交。若已实际检索到指定场地的有效容量依据，可在查询空闲前安全拒绝，必须能定位条文和检索事件；无依据不能省略查询。不强求完全相同的工具次数、顺序或UUID。首批比较器错误地对有依据的越界拒绝也要求查询，原误报已保留。
- 业务：封存的MySQL有效预约数量及所有预约条件符合独立预期；每个初始状态为空。沿用T08安全规则，用户确认、幂等与业务一致性也必须成立。
- 关系：两边先分别匹配独立预期，再比较应变字段集合；这样“两边同错”不会因输出相同而通过。应保持字段也逐项检查。

正常完整执行下的错误字段、缺失必要工具或错误SQL结果为`failed`；未完成/平台错误/取消/缺证据/seed不同为`inconclusive`；事件或artifact完整性异常为`error`，不会算作通过。原始Agent回复不参与通用语义评分，也不使用judge角色。

接口只读计算，不触发模型/工具，不写回旧断言、事件、运行或执行结论。返回比较器版本、观察输入哈希和证据引用。验收脚本另存完整关系报告，历史报告按目录保留；以后用不同代码读同一运行时，应比较返回版本，不能冒称旧判定未变。

## 界面与验证边界

运行页增加“变形对照”：关系选择器、原句/变形句、预期/实际字段、应保持/应变化、工具及MySQL事实、事件定位与版本详情。390px使用单列并允许表内横向阅读，凭据只在页面内存；刷新失败清空旧结论。

`verify_metamorphic.py`显式二选一：`--offline`使用标注值驱动的离线模型替身，只检验基础设施；`--real-model`使用独立T10预算与真实DeepSeek。两种模式均使用临时真实MySQL/Redis、相同Agent/工具/执行器，结束清理自有资源。`--review --ui`可临时保留阅读环境：移除模型密钥、关闭付费开关，不运行Worker/派发器，页面只读取既有事实。stop_file及到期时间在会话JSON中。

本项没有新建Linux双Worker实验，不宣称已完成T11生成器、T12裁判、T13正式数据集或完整Skills/向量检索。
